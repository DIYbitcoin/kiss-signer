# Roadmap

Every feature, and whether it ships today. Status describes the normal beta
firmware unless a row says otherwise.

Legend: **done** shipped and tested · **partial** works with caveats ·
**gated** built but deliberately unavailable · **planned** not started.

"Tested" here means the desktop suite in `sim/` passes against reference
vectors. Nobody outside the project has reviewed any of it. See
[`docs/security-plan.md`](docs/security-plan.md).

## Signing

| Feature | Status | Notes |
|---|---|---|
| Single sig Native SegWit (BIP84) | done | `m/84h/0h/0h`, testnet on `84h/1h` |
| PSBT over animated QR (BC-UR) | done | Both directions |
| PSBT over SD card | done | Writes `<name>-signed.psbt` beside the source |
| On-device re-derivation of every output | done | Change verified, not trusted |
| High fee and dust cautions | done | Acknowledged, never blocking |
| RBF disclosure | done | On the sign screen, with a card saying which answer it is |
| Locktime disclosure | done | In DETAILS, with a plain words note |
| Silent Payments receive (BIP352) | done | Address, plus scan key export behind a deliberate hold |
| Silent Payments send (BIP375) | done | Destination derived on the device, DLEQ proof generated and verified |
| Silent Payments spend (BIP376) | done | Both Y parities; a tweak that does not reproduce the on-chain key is refused |
| Silent Payments scan key export (BIP392) | done | `sp(spscan)` descriptor |
| Multisig | planned | No timeline |
| Taproot key path wallet | planned | P2TR appears today only on the Silent Payments path |
| Message signing | planned | |

Silent Payments is implemented in both directions and every vector in
`sim/test_sp.c` passes, cross-checked against the embit SP fork, including the
BIP374 DLEQ vectors and a Sparrow-generated fixture. What it has not had is a
real network round trip at scale or any outside review, and coordinator support
for BIP375 and BIP376 is still thin.

## Keys and storage

| Feature | Status | Notes |
|---|---|---|
| BIP39 generation, 12 or 24 words | done | 128 or 256 bits of entropy plus checksum |
| Camera plus hardware TRNG entropy | done | The camera hash is mixed with `esp_fill_random`, neither source decides alone |
| Restore by typing words | done | |
| Restore by SeedQR | done | |
| Passphrase, typed per session, never stored | done | Every passphrase is valid, so there is no wrong passphrase error |
| Backup verification against paper | done | Reports a mismatch by word position, never shows the stored words |
| FLASH storage | done | **Not encrypted in the normal beta**, so a chip dump reveals the words |
| SD CARD storage | done | Sealed to a device key, so the card alone is inert |
| AMNESIC storage | done | RAM only, cleared on lock or power off |
| Duress wallet | done | See the note below, the direction is the opposite of what you might expect |

**How the duress wallet actually works**, because it is easy to state backwards.
Drawing plain KISS opens the **decoy**: a real, working, funded signer with no
passphrase prompt at all. The owner's real wallet lives behind KISS plus one
extra configured stroke, and only that path reaches the passphrase keyboard.
This is deliberate. A passphrase field on screen is itself a tell, and a
KISS-branded device where drawing KISS does nothing is more suspicious than one
that opens a modest wallet. See `main/wallet_duress.h`.

## Platform and security

| Feature | Status | Notes |
|---|---|---|
| No radio in the release build | done | The link fails if any radio or networking object appears |
| ESP32-C6 held in reset from the first instruction | done | Every boot, pad latched |
| Reproducible builds | done | CI rebuilds and hashes must match |
| GPG signed releases | done | `SHA256SUMS.asc`, regenerated by `tools/make_web_release.sh` |
| minisign second signature | optional | Emitted when the key exists; `release.json` reports honestly which signatures are present |
| Installer artifacts gated on VERSION | done | `tools/check_installer_version.py` in CI |
| Flash encryption, RELEASE mode | in progress | Build profile complete, hardware testing underway. First boot burns eFuses and cannot be undone |
| NVS encryption | in progress | Ships with the same encrypted profile, since the words live in NVS |
| Rollback protection | follows flash encryption | Not a separate feature. RELEASE mode disables serial reflashing, and a device that cannot be reflashed cannot be downgraded |
| Downgrade warning on screen | planned | Record the highest version ever run in NVS, say so on the home screen if an older one boots |
| Secure boot v2 | planned | Follows flash encryption; both burn eFuses and should be burned together |
| Release hashes signed by the device itself | planned, post v1 | A bitcoin message signature from a KISS device, so the signer vouches for its own firmware. See [`docs/installer/SIGNING.md`](docs/installer/SIGNING.md) |
| External security audit | planned | Not scheduled |

## Known gaps

- **The normal beta does not encrypt flash.** A FLASH wallet is extractable by
  someone with the device and the right equipment. Use AMNESIC, or SD, or wait
  for the encrypted build, for anything that matters.
- **No audit.** Nobody outside the project has reviewed the signing path, the
  PSBT parser, or the BIP39 and BIP352 implementations.
- **No secure boot**, so an attacker with prolonged physical access to an
  unencrypted device can flash modified firmware and the interface will look
  identical. See [`docs/security-plan.md`](docs/security-plan.md).
- **Silent Payments has no outside users yet.** The vectors pass and Sparrow
  fixtures parse, but coordinator support for BIP375 and BIP376 is early.
